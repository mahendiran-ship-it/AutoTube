# Providers: what is supported, what is verified

"Verified" = exercised by an automated test with mocks, or run for real in the development sandbox (which has no internet allow-list for
stock/feeds and no GPU). Anything not verified live is marked **mock-tested only**; first run on your machine is its real test —
`python main.py doctor` tells you precisely what works.

| LLM | OpenAI-compatible (llama.cpp `llama-server`, LM Studio…) | enable in settings | mock-tested |
| LLM | none | — | extractive no-AI fallback; video is flagged and never auto-published |

## Fallback behaviour (bounded — no endless retry loops)
* LLM: at most `ai.max_attempts_per_call` (2) attempts across providers, one JSON-repair re-ask, then the stage fails with a readable error or uses the flagged extractive fallback.
* Visuals, per scene: AI video → stock video → stock image → AI image → procedural. A failure in one provider moves to the next; procedural cannot fail for lack of the network.
* Each pipeline stage retries `pipeline.max_stage_retries` times with backoff; QC-triggered re-renders are capped by `pipeline.max_qc_repair_attempts`.

## Licensing
Every stock asset stores provider, license name/URL, author and attribution text in the `licenses` table. Attribution is added to the
description when required. NASA third-party (`secondary_creator`) media is skipped. **You** remain responsible for checking that your
use of an asset is allowed; the app records what the provider stated.
